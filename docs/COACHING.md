# AIコーチ継続相談・PDCA仕様（2026-11-04）

## 目的

日をまたいでも前回の仮説・合意した変更・確認すべき結果を引き継ぎ、実績と比較して次の計画を相談する。成果の意味を認める反応と、読みやすい回答を両立する。

## 記録の区別と保存先

| 種類 | 保存先 | 扱い |
|---|---|---|
| 相談・AIの提案 | chat_messages | ユーザーの合意や実施結果とは区別する |
| 未保存のメニュー下書き | assistantのcontentにcoach-v1 JSONとして本文と同時保存 | 履歴取得時に本文と確認カードに復元。旧プレーンテキストとも互換 |
| 合意した計画 | planned_menus | 確認カードで日付・方針を確認して保存した時点で成立 |
| 仮説・試す変更・次の確認 | planned_menus.notes | 人が編集できるラベル付きテキスト。備考欄でも閲覧・修正可能 |
| 実施結果 | workout_logs / workout_sets / notes | 計画と同日・同種目は照合候補。実施完了・効果の証明とはみなさない |

初版は既存テーブルで動作し、DDL・データ移行は不要。未解決課題の独立した管理テーブルやベクトル検索は未導入。

## 会話と証拠の取得

- 日付でセッションを打ち切らない。DBの新しい発言から最大120件、本文合計48,000文字以内を取得し、時系列に戻す。最初がassistantになった場合は除く。
- 履歴表示とチャットAPIは同じ選択関数を使用。画面の参照開始日は取得できた範囲を示す。全履歴を常に参照する旨は表示しない。
- 旧実装の同時刻user/assistantはuser→assistantに並べ直す。新しいペアはcreated_atを1msずらして保存する。
- 実績ログは直近40件とその全セット、保存計画は作成順で直近30件、体組成20件、疲労メモ10件。範囲外の履歴・計画は自動検索しない。
- 会話取得や必要な記録取得のエラー時は、記憶なしの回答を生成せずエラーを返す。生成後のペア保存失敗も成功扱いにしない。画面では入力を戻して再送できる。
- メニューの保存に失敗した場合は確認カード内で再試行可能。下書きUUIDを保存IDに使い、同じ内容の再送は重複作成しない。

## 回答方針

- 一律500文字の上限と「称賛を省略する」指示を撤去。
- 冒頭に短い要点または成果への反応。その後に必要な比較・根拠・次の行動を続ける。
- 目標到達・自己ベスト・継続・課題改善には具体的な意味を認める。日常的な定型の励ましは繰り返さない。
- 初期プロフィールの重量は現在値と断定しない。新しい実績・本人の訂正を優先する。
- 結果の原因は証拠がなければ仮説。一度の改善だけで因果を確定しない。
- 重要な不足情報を質問する。未確認の実施・効果・合意は作らない。
- Sonnet 4.5のcoach_replyツール出力を実行時にも検証。max_tokens=4096は技術的な上限であり回答の目標長ではない。途中終了は履歴へ保存しない。
- ログにはモデル名、usage、stop_reason、参照発言数、所要時間を記録。会話本文や認証キーは計測ログに出さない。

## 日程

- 日付境界はJST。クライアントから送られたsession_idを保存日の根拠にしない。
- 固定曜日はchest=土、back=日、legs=火。AIは意図を返し、コードが実日付を決める。
- next_training: 基準日より後の該当曜日。同じ曜日の直後なら7日後。
- after_days: 基準日から指定日数後。explicit: ユーザー明示日。
- 基準日は今日または取得した記録・会話で確認できる日付。曖昧な場合は再確認する。
- 曜日はYYYY-MM-DDからUTCの暦日計算で描画。日付にローカルタイムゾーンの時刻加算を混ぜない。
- AI本文の絶対日付は{{date:YYYY-MM-DD}}で返し、コードで描画。一般的な年付き日付表記の曜日誤りも整形する。単独の「次の日曜」等すべての自然言語表現の正しさを保証するものではない。
- 保存前の確認カードはコードで作った同一日付を表示・保存に使用。日付変更可。通常の種目曜日と違えば警告と明示確認を表示する。
- 新しいチャットはSAVE_MENUマーカーによる自動保存を使わない。旧API入力・既存の保存メニューとは互換。

## UI

- スマホはアシスタントを利用可能幅まで広げ、本文15px・行間・段落間余白を確保。PCは読み幅を制限する。
- 回答全文を表示し、通常スクロールで読む。読んでいる途中は新着で強制的に末尾へ移動しない。
- 「引き継いでいる計画・次の確認」は直近3件を展開して読める。記録候補へのリンクを表示。
- 確認カードで実施日、種目一覧、仮説・変更・確認項目・備考を確認する。PDCA項目は保存前に編集可。
- 保存後は次回メニュー画面から修正する。下書きの再保存による二重登録を防ぐ。

## 検証と今後

自動検証: JST午前0時、朝9時、土曜→翌土曜、月末・年末・閏日、曜日変更、誤った曜日表示、日をまたぐ履歴、未実施の扱い、保存失敗、出力打切り、範囲レップ、長文表示、確認前に保存しないこと。

Claude実APIの合成会話: 140kg目標達成、翌週の肩の張り確認、土曜の7日後の計画、140→135kgへの訂正。生成品質は固定の保証ではなく、実際の使用感と同じケースの反復で評価する。

残る制約: 参照範囲外の古い相談を探す検索、未解決課題の状態遷移、計画変更の完全な版管理、複数端末の同時送信の直列化、ストリーミングは今後の対象。計画・実績の一致から効果を自動確定しない。

Vercelの関数制限はプランとFluid compute設定に依存する。古い「Hobbyは必ず10秒」という記載は一律には適用できない。外部APIルートはmaxDuration=60を指定し、デプロイされた関数設定と実測で確認する。
